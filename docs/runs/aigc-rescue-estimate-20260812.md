> 日期：2026-08-12
> 基准：`retarget_square_public_v2`，完整分母 300

> 成功定义：AIGC 输出达到自动评价 Proxy A/B；单纯返回图片另行统计

Hybrid 的文件交付率可以是 100%，因为 AIGC 失败时仍返回传统候选；但 Proxy C 回退不冒充质量成功。Hybrid 的最终“自动质量均分”没有外推：4 个 Qwen4 失败任务未做 AIGC 实测，而且 AIGC 与传统候选的 proxy score 未经人工校准，不应只凭成功率反推均分。

### 1.3 决策结论

- 只看零外部成本：选 Qwen4 Conditional，不接 AIGC，质量成功率 93.0%。
- 允许约 6–12 元 API 预算：选 Qwen4 Conditional Hybrid，点估计 96.3%，每新增救回一张约 0.60–1.20 元。
- Rules Hybrid 适合作为无法部署内部 VLM 时的退路，但质量更低、AIGC 调用更多。
- 全部 AIGC 的质量成功率估计反而低于 Qwen4 不接 AIGC，且 API 成本约高 15 倍，不推荐。

## 2. Qwen4 未成功时，AIGC 能否挽救

能挽救一部分，但不是全部。

Full300 的 Qwen4 Conditional：

- 原始 Proxy A/B：279/300，即 93.0%；
- Proxy C：21/300；
- 这 21 张全部被 Qwen4 标记为 `CALL_EXTERNAL_AIGC`。

AIGC30 直接覆盖了其中 17 张：

- 10/17 返回图片，生成成功率 58.8%；
- 8/17 达到 Proxy A/B，真正救援率 **47.1%**；
- 2 张虽然返回图片，但仍是 Proxy C；
- 7 张没有得到图片；
- 成本 4.8–9.6 元。

漏测的 4 张全是 `landscape_architecture_structure / aspect_extreme`。AIGC30 中同场景 4 张的结果是：3/4 返回图片、2/4 达到 Proxy A/B。因此不再付费调用，使用同场景点估计：

```text
估计生成成功 = 已实测 10 + 4 × (3 / 4) = 13
估计真正救回 = 已实测 8 + 4 × (2 / 4) = 10
估计最终成功 = Qwen4 原成功 279 + 救回 10 = 289 / 300 = 96.3%
估计成本 = 已实测 4.8–9.6 + 同场景 4 张 1.2–2.4 = 6.0–12.0 元
```

17 张直接样本的救援率 95% Wilson 区间为 26.2%–69.0%。若把这个采样不确定性投影到 21 个触发项，最终 Full300 成功率大约落在 94.8%–97.8%；这只是统计区间，不是 SLA。

漏测任务：

- `commons-41aecd3a8a4a__square-1024x1024`
- `commons-4d8dee352567__square-1024x1024`
- `commons-53d86ead4d3d__square-1024x1024`
- `commons-6c5c711892ee__square-1024x1024`

## 3. 全部使用 AIGC

有两种合理估法，必须同时披露。

### 3.1 困难集直接外推

AIGC30 是困难压力集，不是从 Full300 随机抽样：

- 21/30 返回图片，生成成功率 70.0%；
- 16/30 达到 Proxy A/B，质量成功率 53.3%；
- 29/30 属于可能计费请求；
- 30 张成本 8.7–17.4 元。

直接乘 10，得到 Full300 压力口径：

- 约 210 张返回图片；
- 约 160 张质量成功；
- 成本 87–174 元；
- 最坏预算 180 元。

由于只有 30 张，生成成功率的 95% Wilson 区间为 52.1%–83.3%，质量成功率区间为 36.1%–69.8%。

### 3.2 按 Full300 的 Qwen4 难易分层重加权

AIGC30 中：

- Qwen4 失败层 17 张：10 张生成、8 张质量成功；
- Qwen4 非失败对照层 13 张：11 张生成、8 张质量成功。

按 Full300 实际的 21 张失败层、279 张非失败层重新加权：

```text
估计生成成功 = 21 × (10/17) + 279 × (11/13) = 248.4 / 300 = 82.8%
估计质量成功 = 21 × (8/17) + 279 × (8/13) = 181.6 / 300 = 60.5%
估计成本 = 89.6–179.3 元
```

这比直接压力集外推更接近 Full300 的难易比例，但 13 张对照也经过困难样本筛选，仍不能视为无偏随机估计。因此面向预算和承诺时，应把全部 AIGC 表述为：

- 返回图片率估计 **70%–82.8%**；
- 质量成功率估计 **53.3%–60.5%**；
- 成本约 **87–180 元**。

## 4. Qwen4 自动换 AIGC

Qwen4 的触发集合恰好等于它的 21 张 Proxy C，不会在已经成功的 279 张上浪费 AIGC 调用。

估计结果：

- 调用 AIGC：21 次；
- AIGC 返回图：约 13 张，触发集合内生成成功率 61.9%；
- 真正救回：约 10 张，救援率 47.6%；
- 最终质量成功：289/300，即 **96.3%**；
- API 成本：**6.0–12.0 元**；
- 预算硬上限：12.6 元；
- 每救回一张的增量 API 成本：约 **0.60–1.20 元**。

Agent token 由公司内部提供，本口径中成本为 0。延迟只会加在 21 个触发项上；其余 279 张不等待 SeedDream。

## 5. 规则路线自动换 AIGC

冻结规则路线原始结果：

- Proxy A/B：258/300，即 86.0%；
- Proxy C：42 张；
- 规则实际标记 `CALL_EXTERNAL_AIGC`：34 张；
- 仍有 8 张 Proxy C 没有触发外部生成。

AIGC30 直接覆盖其中 17/34：

- 10/17 返回图片；
- 8/17 达到 Proxy A/B；
- 成本 4.8–9.6 元。

这个 route-conditioned 样本恰好是触发总量的一半，因此按 2 倍外推：

```text
估计 AIGC 返回图 = 10 × 2 = 20
估计真正救回 = 8 × 2 = 16
估计最终成功 = 258 + 16 = 274 / 300 = 91.3%
估计成本 = 4.8–9.6 × 2 = 9.6–19.2 元
```

规则 Hybrid 的最终成功率估计区间约为 89.0%–93.8%。它比纯规则的 86.0% 好，但明显低于 Qwen4 Hybrid 的 96.3%，同时预计多花 3.6–7.2 元，因为规则触发 34 次而 Qwen4 只触发 21 次。

如果修改规则，强制 42 个 Proxy C 全部调用 AIGC，按 AIGC30 中规则失败样本的 9/20 救援率估计，最终约 92.3%，成本约 12.0–23.9 元，仍不如 Qwen4 Hybrid。

Qwen4 Hybrid 同时利用了两个互补事实：Qwen4 不接 AIGC 已经解决 93% 的任务；AIGC 对这条路线的失败项仍有约 48% 的挽救能力。全部用 AIGC 会丢掉已有稳定性，并把 API 成本放大约 15 倍。若公司内部 Agent 推理和 token 都不计费，那么 Qwen4 Hybrid 的增量现金成本只来自 21 次 SeedDream 请求。

## 7. 估算边界

1. Proxy A/B 是未完成人工盲评校准的自动指标，不是线上业务通过率。
2. AIGC30 是困难分层样本，全部 AIGC 的 300 张外推不是随机抽样估计。
3. Qwen4 漏测 4 张使用同场景 2/4 点估计，样本很小。
4. SeedDream 不返回实际账单；成本采用用户给出的 0.30–0.60 元/次，以及实际记录的明确不计费/可能计费状态。
5. AIGC 超时可能已经计费，因此成本估算没有把超时简单当作 0 元。
6. 本次只做离线估算，没有新增任何付费 API 调用。

## 8. 复现

```powershell
.venv\Scripts\python.exe scripts\report_aigc_rescue_estimates.py `
  --output local_data\aigc-rescue-estimate-v2.json
```

脚本严格核对 Full300 两轮 300 个 Qwen4/规则 decision、AIGC30 的 30 个生成终态和 30 个评价结果；分母不匹配会直接失败。
